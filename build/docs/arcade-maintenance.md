## Add a game or a build

Add a build to its existing source family when it is actually a version of that game. Similar titles alone are not identity evidence. Keep different games separate and keep original builds when publishing a repair. Give each source build a unique ID, readable label, recorded date, public HTTPS URL, size where known, and honest check status. A source repository or an uncompiled native project is not a playable URL. Add exclusions and selected-version overrides to `arcade-curation.json`; never reintroduce an excluded entry through an archive refresh without Alex requesting it.

The family supplies a title, description, genres, controls, kind, first/last recorded dates, image metadata, and a `preferredId` that exists in `versions`. Existing portfolio text and featured selections are authored content; the recovery catalog must not silently rewrite them. PASTA remains a collection with its six authored game choices.

Every source family needs a local image. Prefer an authentic screenshot or existing authored artwork. Preserve the complete screenshot composition. Records with `imageKind: "title"` render a plain accessible title panel using the curated title, without screenshot-status captions. Never present a title panel as a gameplay capture. Referenced raster images are 800 × 450 WebP.

## What a check means

| Status | Evidence required |
| --- | --- |
| `input-checked` | A deliberately tested input caused a visible in-game response. Describe the limited scope in `qaNote`. |
| `launch-checked` | A title screen, interface, or game scene rendered and was visually reviewed. This does not establish gameplay. |
| `menu-only` | Only the menu was checked. |
| `link-checked` | The public entry responded; no gameplay claim. |
| `launch-unverified` | A launch attempt did not establish a running game. Describe the observed limitation without claiming a source defect. |
| `environment-limited` | The test environment could not supply a required graphics capability. Do not call the game broken on that basis. |
| `broken` | A demonstrated runtime defect interrupted that exact build. Preserve the original and add any repair separately. |
| `download` | A native download exists; it has not necessarily been executed. |
| `unavailable` | No playable or downloadable build is hosted. Exclude it from the public selection. |
| `untested` | No stronger applicable evidence. |

Check evidence belongs to an exact build and destination, not merely a family title. Keep `checkedAt` and a concise `qaNote` in the source records; these are not public catalogue fields. Never expose private source paths, account data, credentials, or private file references. A short check does not certify all levels, endings, saves, audio, mobile controls, or desktop compatibility. A graphics-limited check alone is not grounds for exclusion.

The public archive stores restored runtime assets separately. Its bounded upload process verifies exact file and chunk fingerprints and closes its upload window after a release. The arcade links to those public copies while preserving the original source projects' existing audiences.

## Discovery behavior

Search, genre/control/type filters, title/size/recent-play sort order, view mode, and pagination operate locally after a single catalog fetch. A share URL identifies a game; old build/status parameters are ignored. Favorites and recent plays remain in the visitor's own browser and are pruned to retained games. The no-script directory keeps the selection navigable without JavaScript. Actual games load only after the visitor follows a launch link.
